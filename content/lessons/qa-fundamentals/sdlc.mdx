Sebelum menguji, kamu perlu tahu bagaimana sebuah software dibuat. Alurnya disebut **Software Development Life Cycle (SDLC)**.

## Tahapan SDLC

| Tahap | Kegiatan | Peran QA |
|---|---|---|
| 1. Analisis kebutuhan | Mengumpulkan dan memahami kebutuhan | Meninjau kebutuhan, mencari yang ambigu |
| 2. Desain | Merancang arsitektur dan tampilan | Meninjau desain, mulai merencanakan test |
| 3. Pengembangan | Developer menulis kode | Menyiapkan test case dan data uji |
| 4. Testing | Menguji produk | Menjalankan test dan melaporkan bug |
| 5. Deployment | Merilis ke pengguna | Smoke test setelah rilis |
| 6. Maintenance | Memperbaiki dan mengembangkan | Regression testing |

## Model SDLC

- **Waterfall:** tahap berjalan berurutan; tahap berikutnya dimulai setelah tahap sebelumnya selesai. Cocok untuk kebutuhan yang jarang berubah.
- **Agile:** pengembangan dilakukan bertahap dalam iterasi pendek, sehingga mudah menyesuaikan perubahan. Model ini paling banyak dipakai saat ini.

<Tips>QA sebaiknya terlibat sejak tahap analisis kebutuhan, bukan hanya di tahap testing. Pendekatan ini sering disebut shift-left testing.</Tips>

## Ringkasan

SDLC dimulai dari analisis kebutuhan dan berakhir di maintenance. QA punya peran di setiap tahap, bukan hanya saat testing.
